# M4-09 implementation evidence

Each human now manages only their own Participant: seat changes between Hands, sitting out and resuming, top-ups and rebuys, Stand Up and Leave Table. Nobody else, the Table Owner included, can do so for another human; a request naming another human's Participant is rejected with 403 `not-your-participant`, `leave-table` included.

A sit-out, Stand Up or Leave Table asked for during a Hand, which lasts until its payout phase ends, is recorded as an after-Hand request in the Persisted Table Session and shown to everyone as a pending change. When the payout phase ends the server applies all of the Hand's requests in one committed transition, before Deal is accepted. Leave Table stands the Participant up if seated and ends their membership, so the table leaves their saved list and one of the 20 places is freed. A Guest who left rejoins through the Join Link as the same Participant under their original name, with their history. An owner who left keeps the table in their saved list, marked as left, and returns with `POST /:id/rejoin-table`, without the link. The behavior is described in the [server protocol reference](../server-protocol.md#after-hand-requests).

Server tests in `apps/server/test/after-hand-requests.test.ts` drive a `ManualClock` through a deferred sit-out, Stand Up and Leave Table at a Practice Table; idempotency (the same request ID, a fresh ID for the same change, a late retry) and chip conservation (what is cashed out plus what stays is what was there); a restart during the payout phase and an outage that outlasts it; superseding requests; moves and top-ups refused until the payout phase ends; immediate application between Hands; a Practice human who never sat down; a Deal that reaches the table before its wake-up; and, at an Online Table with two Guests, a seated Guest leaving mid-Hand and rejoining through the link, the freed place, ownership staying with an owner who is away, and the refusal of every request that names another human. Pure web tests in `apps/web/test/self-service.test.ts` cover which controls apply now, apply after the Hand or are unavailable.

## Browser check

On 2 November 2026, using the [schedule browser fixture](../local-development.md#schedule-browser-fixture) (system clock, automatic Bots; API port 3139, Vite port 5239) and two isolated Chrome sessions, one per Guest:

- At a heads-up Practice Table, during Hand 01, Table options offered "Sit out after this hand", "Stand up after this hand" and "Leave table after this hand" with top-up disabled. After "Sit out after this hand" the dialog and the seat both read "Sitting out after this hand". After folding, the seat read `Won 20` and then `Sitting out`, and the Deal button read "Return & deal".
- In Hand 02, "Leave table after this hand", then folding, returned the page to its saved tables with "You left the table.". The table remained listed as "You left", "Return to table". Opening it returned to the same table, Hand 02 complete, with the seat free ("We'll return you to an open seat.").
- At an Online Table, a second Guest joined through the link, opened Table options (unseated: "Leave table" applies at once) and left. The table dropped from their saved tables. Reopening the Join Link showed "Return to Ann's table" and "You'll come back as Ben", and returned them to the table.
