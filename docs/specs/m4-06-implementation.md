# M4-06 implementation evidence

A Practice Table can now be played against the clock. Creation offers an Action Time Limit of 15, 30 or 60 seconds under "Customize table & bots", off by default. Under a limit, each human Action Window carries its exact Action Deadline (`deadlineAt`, the window's `opensAt` plus the limit) in every view and live update. Bot windows never have one. An Online Table's limit is still stored and shown only, until Automatic Dealing (M4-10) enforces it with the after-Hand sit-out.

A human `act` that the server receives after the deadline is rejected with 409 `action-deadline-passed`. That holds both while the Timeout Action is still due and after it has applied. An act received at the deadline itself is on time and is never displaced. From the first millisecond past the deadline, the server plays the Timeout Action (Check when legal, otherwise Fold) as an ordinary accepted act with request ID `timeout:<decisionId>` and fingerprint source `server`, inside the table's FIFO. Later missed decisions in that Hand time out too. The human is never sat out, and the next Hand waits for their Deal. A deadline that expired while the server was down resolves at startup, before any request is served. Timeout Actions start automatic post-action analysis and count in Decision Scores, Action Rank Scores and Hand and Session summaries. The behavior is described in the [server protocol reference](../server-protocol.md#play-timing).

The Trainer shows the countdown in the action tray and on the acting seat. It disables action controls at the deadline on its estimate of the server clock, and explains a late-action rejection ("Your time ran out." with the server's message).

Server tests in `apps/server/test/action-deadlines.test.ts` drive a `ManualClock`. They cover the deadline in views (and none for Bots or untimed tables), the creation options, a late act and the Fold timeout, an act exactly at the deadline, Check timeouts on every later street with Deal still required, a deadline that expires during an outage across two restarts, a Timeout Action whose commit fails and is retried, one whose COMMIT proves never to have applied (played once under a fresh derived ID), and scoring through automatic analysis and both summaries. Pure web tests in `apps/web/test/presentation.test.ts` cover disabling controls at the deadline (also through the clock offset), the countdown, and its re-render instants.

No browser check was recorded: the fixture and Vite were stopped by the host for low memory partway through. The creation option was seen in the browser (off by default; choosing 15 seconds added "15 seconds to act" to the preview).
