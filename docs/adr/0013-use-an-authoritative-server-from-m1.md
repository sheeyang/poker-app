# Use an Authoritative Server from M1

M1 will run each authoritative Cash Game on a Node.js Fastify server rather than in the browser. The server generates and retains the hidden master seed, executes human and Bot actions, exposes participant-specific views over HTTP and WebSocket, and persists private Table Session Records in PostgreSQL through Drizzle. The React and Vite client is untrusted: it sends intentions using safe contracts and receives participant projections during gameplay or explicitly authorized completed-Hand Research results, without hidden configuration, authoritative records, live hidden cards, or direct access to engine or Research APIs. This introduces deployment and persistence work in M1 but establishes the intended security boundary before gameplay, strategy execution, and hidden-information analysis are built around a browser-owned authority.

M1 is locally deployed for a single application user with one backend server process and local PostgreSQL. A server-issued opaque HttpOnly cookie identifies the local user, while stable ParticipantIds identify the human and Bots within each Table Session; application-level Table Ownership governs management operations without entering the engine model.

CashGame remains inside the trusted server execution boundary: neither browser application imports, instantiates, restores, or receives a CashGame, and live game instances are never serialized as client data. Any computation requiring authoritative information is performed within the server deployment, through JobRunner where applicable, and the client receives only the explicitly permitted plain-data result through contracts. This also applies to completed-Hand replay and Research; server execution does not relax participant visibility or the completion gate on privileged inspection.
