# Retain Numerical Trainer Analysis Independently of Gameplay

M2 proves the complete numerical analysis pipeline using the existing baseline Strategies, with stronger Strategies remaining separate scope. The application provides Policy probabilities, concrete sizings, the Reference Strategy's selected action, and numerical alignment scores; the human interprets them, and the application does not give advice or label decisions good or bad. The established scoring formulas and package boundaries in ADR-0006, ADR-0008, and ADR-0019 still apply.

Every accepted human decision automatically triggers a nonblocking analysis request, including when Live Analysis is off. Each new analysis request freezes the currently selected complete Reference Strategy and the participant-safe inputs for its target; accepted human actions store no Reference Strategy assignment. Reuse matching Live Analysis results or work only when the full analysis identity matches. Results remain associated with their original requests and decisions as play advances or preferences change, and analysis never delays acceptance of a legal human action or introduces a feedback acknowledgement gate into poker progression.

The Reference Strategy and Live Analysis setting persist per Table Session, are shared across its owner's tabs, and restore after restart. The default Reference Strategy composes UniformChoicePolicy with ProbabilitySelector, and Live Analysis defaults to off. Enabling Live Analysis permits evaluation before the human acts without changing any Bot's Playing Strategy.

One HTTP get-or-start operation returns cached successful results, reuses queued/running matching work and returns pending, schedules missing work and returns pending, or returns a matching failure without restarting it. Explicit Retry retries only failed analyses with their original inputs and seeds, reusing successful results and active jobs; changing the selected Reference Strategy creates a different analysis request rather than changing the inputs of an existing retry. Scheduling, caching, deduplication, and retry behavior belong to the analysis module, independently of connection delivery.

Successful cached Analysis Results persist with their complete Strategy descriptors, implementation versions, frozen input fingerprints, effective seeds, scoring method, and other reproducibility metadata. Queued/running jobs and failure states may remain transient; M2 requires neither a durable analysis obligation nor guaranteed background completion. After restart, requests schedule missing work without an automatic recovery sweep. This retains reproducible derived results without introducing durable job recovery or assigning Strategies to accepted human actions. New numerical retention covers human Reference Strategy analysis, while accepted Bot actions retain the existing selected-action provenance without adding Playing Policy distribution retention.

M2's backend includes individual Decision Scores and Action Rank Scores plus Hand and Table Session arithmetic means of both measures. Each summary request freezes its included decision IDs, one currently selected complete Reference Strategy for all of them, and the captured poker revision; responses identify the request and return that revision and the decision count. Summary-driven backend reanalysis is included in M2, while replay and comparison tools remain M4. Return complete averages only when every required decision analysis has succeeded; otherwise return pending or error status, with error taking precedence over pending and no partial average or zero substituted for missing results. A summary with no human decisions has no numerical score. Overall-history summaries remain M4 scope.

Analysis completion and failure use the existing Table Session WebSocket and the shared contracts union defined in ADR-0017. Updates identify the exact immutable analysis request and execution attempt; obsolete attempts, superseded requests, and delayed HTTP pending responses cannot replace newer state. Extend the existing connection modules for typed delivery, cleanup, and reconnection, keeping analysis orchestration in the analysis module and requiring no new connection class. Normal operation requires no polling; after the connection is established, refresh current analysis through HTTP to recover missed updates and reconcile transient state after restart.

M2 exposes controls and numerical results through the Playground for engineering validation. M3 owns when and how the product requests summaries and presents results, including post-action feedback; the intended presentation is a Hand summary after the Hand ends and a Table Session summary when the user finishes the session. M2 needs no explicit session-ending lifecycle solely to support summaries. The presentation guidance in ADR-0008 belongs to M3. This separates numerical analysis and retention from feedback timing and presentation rather than making analysis depend on an interface flow.
